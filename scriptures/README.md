# Scriptures in the Thiruppugazh

Working notes for a repository of the Ramayana, Mahabharata, Puranic and other scripture
stories that Arunagirinathar weaves into the Thiruppugazh. This folder is research material,
not app code: nothing here is bundled into the app or touches the DB.

**Start here each session:** read this file, then `STATUS.md` (what is done, what is next), then `WORKFLOW.md` (the repeatable process for a new deity such as Shiva, with a kickoff prompt).

## Layout

```
scriptures/
  README.md                    this file: goal, method, conventions
  STATUS.md                    running log and next steps (update at the end of every session)
  import/
    vishnu-shiva-categories.json   app backup file (version 1): creates the "Vishnu Songs" (228) and "Shiva Songs" (238) categories when loaded through Settings > Import; no personal data, not bundled in the app
  scripts/
    shortlist_maruga.py        regenerates the Vishnu shortlist from assets/thiruppugazh.db
  vishnu/
    shortlist.md               one row per song, readable index  (generated)
    shortlist.json             every hit with prev/next line, story hints  (generated)
    excluded.md                look-alike words rejected, with the reason  (generated)
    song-story-map.txt         HAND-WRITTEN: which story each of the 272 songs alludes to (edit this, not generated files)
    SOURCES.md                 what was checked online, and what is still unchecked
    STORIES.md                 index of the stories (episodes) with song, reference and Divya Prabandham counts  (generated by build_master.py)
    by-song.md                 per song: its stories, linked  (generated)
    master.json                every story with all references, Divya Prabandham verses and songs  (generated)
    stories/<domain>-<episode>.md   one file per story: brief, ALL references (Valmiki, Kamba, Mahabharata, Bhagavata, Vishnu Purana, Divya Prabandham), the songs and their lines  (generated)
    ramayana-verses.md         per Ramayana song: episode + Valmiki sarga.shloka + Kamba padalam verse  (generated)
    ramayana-episodes.md       per episode: the cited Valmiki shlokas and the quoted Kamba verses  (generated)
    krishna-verses.md          per Krishna/Mahabharata song: episode + Bhagavata verse + Mahabharata CE line  (generated)
    krishna-episodes.md        per episode: Bhagavata verse ranges with gists, Mahabharata Sanskrit lines quoted  (generated)
    avatar-verses.md, avatar-episodes.md   avatars (Gajendra, Vamana, Narasimha, churning...) with Bhagavata/Valmiki/Kamba verses  (generated)
    dp-ramayana.md, dp-krishna.md, dp-avatars.md and dp/*.json   Nalayira Divya Prabandham pasurams per story, each with the URL opened (written by research passes; not generated)
    general-songs-review.md    re-read of the vague songs; its corrections are applied to song-story-map.txt
  scripts/avatar_episodes.py, build_avatar_verses.py   same pattern for the avatar songs
  scripts/krishna_episodes.py  HAND-WRITTEN: Krishna/MBh episode catalogue + song assignments
  scripts/build_krishna_verses.py checks every cited Bhagavata verse and Mahabharata line exists, then writes the two files above
  scripts/fetch_krishna.py     downloads vedabase.io Bhagavata chapters and the GRETIL Critical Edition Mahabharata
  scripts/ramayana_episodes.py HAND-WRITTEN: episode catalogue + song -> episode assignments
  scripts/build_ramayana_verses.py checks every Kamba verse number exists, then writes the two files above
  scripts/fetch_sources.py, find_kamba.py, find_valmiki.py, vq.py, kamba_q.py, kamba_heads.py: text lookup helpers
                               (download Valmiki/Kamba text into scripts/.cache, which is git-ignored)
  scripts/story_data.py        HAND-WRITTEN: brief + source pointers per story
  scripts/build_master.py      joins the three episode catalogues, story_data.py and dp/*.json into master.json, STORIES.md,
                               by-song.md, stories/ and the reading PDF  (run this last; needs Microsoft Edge for the PDF)
  thiruppugazh-vishnu-stories.pdf   the reading/verification PDF (Part A by song number, Part B by story, Part C songs with no story)
```

`shiva/` follows the same shape (see `shiva/README.md` for the shortlist rule, `shiva/SOURCES.md` for what was checked):
`song-story-map.txt` (hand-read), `refs-sanskrit.json`, `tirumurai-deeds.json`, `refs-saints.json`, and the generated `STORIES.md`,
`by-song.md`, `master.json`, `stories/`, plus `thiruppugazh-shiva-stories.pdf`. Per-deity code: `scripts/deity_<name>.py`,
`scripts/shiva_episodes.py`, `scripts/shiva_story_data.py`, `scripts/shortlist.py --deity shiva`.
Build: `python -I scriptures/scripts/build_master.py --deity shiva` (default is vishnu).
New deity or theme folders (e.g. `murugan-lore/`) follow the same shape.

`sambandar/`, `saints/`, `devi/`, `murugan/`, `ganesha/` and `tamil-lore/` (added 2026-11-10) are generated from a hand-written catalogue in
`scripts/build_new_sets.py` (`python -I scriptures/scripts/build_new_sets.py`). Each has `README.md`, `STORIES.md`, `by-song.md`,
`song-story-map.txt`, `SOURCES.md` and `stories/`. Their song lists are keyword-level (English commentary sweep plus a quoted Tamil line
where one matches); read the set's README before relying on counts.

## Stage 1: shortlist (done, first pass)

Goal: find songs where Murugan is addressed as the *nephew* (மருகன்) of someone. In the
Thiruppugazh this is the usual way Arunagiri refers to Vishnu: Murugan is the son of Parvati,
Vishnu's sister. The phrase is typically preceded by a clause naming a deed of Vishnu
("... வாலி மார்பைத் துளைத்தவன் மருகோனே"), so the line before the keyword is the story clue.

Search is over `songs.lyrics_list` (Tamil, the line array the song page uses) in
`assets/thiruppugazh.db`, opened read-only. Accepted forms: மருகோனே, மருகா, மருகன்/மருகனே,
மருகர், மருமகன், and bare vocative மருக (which is often fused to the next word because the
lyrics are in sandhi form, e.g. `அரிமருக`, `திருமருக`, `மால்மருக`).

Rejected look-alikes (see `vishnu/excluded.md`): தமருகம்/டமருகம் (damaru drum), சமருக் (battle),
மருக்கு-/மருக்கற்புர (fragrance), மருமலர்/மருமறை (fragrance, mystery), மருகு (to wither),
திருமருகல் (a place), மருமகள் (daughter-in-law, song 140).

### Result

| | |
|---|---|
| Songs with a nephew word | **272** of 1340 |
| மருகோனே | 213 songs |
| மருக (bare, fused) | 39 |
| மருகா | 9 |
| மருமகன் | 6 |
| மருகன் / மருகனே | 5 |

Each song has exactly one nephew hit.

### Caveats

- The lyrics are in sandhi form with unreliable spacing, so keyword matching removes spaces
  first. The "Vishnu name seen" split (146 / 126) and the "story hints" are **keyword guesses
  only**. 158 songs have no story hint yet because the keyword lists are short, not because
  the song has no story.
- Not every nephew is Vishnu. Expect a few songs where the uncle is someone else. Stage 2
  confirms each song by reading it.
- Only songs whose Tamil lyrics contain the word are found. A song that tells a Vishnu story
  without the nephew word (for example one that only names Vishnu or narrates the story) is not in this list. See STATUS.md, "Later".

## Stage 2: story by story (first pass done, 2026-10-26)

Planned per-song record (one markdown file per story under `vishnu/stories/`, named
`<story-slug>.md`, e.g. `vamana-bali.md`):

1. Story name and source (Ramayana / Bhagavatam / Mahabharata / other Purana), in one line.
2. Songs that refer to it: id, title, temple, the exact lines, and what each line alludes to.
3. Source-text pointers (kanda/skandha/parva) only where confident; mark uncertain ones.
4. Open questions for the owner.

Rules for this folder:

- Quote lyrics exactly as stored in the DB; never "correct" them. Give the song id every time.
- Mark anything not verified against a primary or reputable source as `(unverified)`.
- Keep Tamil and English side by side where it helps; the owner reads both.
- Generated files carry a header saying so. Do not hand-edit them: change the script and rerun.

## Regenerating

From the repo root:

```
python -I scriptures/scripts/shortlist_maruga.py
```

Reads the DB read-only. Safe to rerun; it overwrites the three generated files in `vishnu/`.
